# Mshwar code review report

- **Date:** 16 September 2026
- **What was reviewed:** the whole monorepo (`apps/web`, `services/api`, `mshwar-database`, `mshwar-brand-foundation`) as it is now on branch `feat/ui-redesign`, including the uncommitted UI redesign.
- **How:** read the code, ran every check the repo defines, started a real PostgreSQL database (16 with PostGIS and pgvector; CI uses 17) to run the API tests, and proved the serious problems with small test scripts. Those scripts ran only in a separate copy and were deleted afterwards.
- **Status:** report only. **No code has been changed yet** (Step 3 says to stop here). One exception: the new `apps/web/src/app/fonts/README.md` from the UI redesign was re-formatted with Prettier so it passes the format check.

---

## 1. Summary

The code is in good shape in many places. It has 93% API test coverage, clean type checks, and careful booking and payment logic inside the database. Row locks, idempotency keys and payment-state guards all work.

But there is **one small config bug that switches off most of the security in production**, and several payment and file endpoints depend on that config being right. Together they allow:

- confirming bookings **without paying**
- **forging payment webhooks**
- **reading any file on the API server**, without signing in

These must be fixed before any real launch. All of them are small fixes.

The trip planner has three logic bugs (return-by, locked stops, "24:00" hours) and one performance problem that can freeze the whole API. On the web side, the main problem is that the site shows **made-up sample listings and prices** when the API fails.

## 5. What is fine (no change needed)

- **Checkout idempotency:** a unique request key per customer, and the same key with a different body returns 422 (tested).
- **Last-seat safety:** reservation happens in SQL with row locks; the API test proves only one of two parallel bookings wins.
- **Payment state machine:** invalid payment and booking transitions are blocked by DB triggers (seen during testing).
